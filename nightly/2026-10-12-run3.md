## 1. Summary for Ian

- **Four new mixer bugs fixed, each with a test that fails on upstream's code.** Two of them matter for voice-over:
  - **A mono voice track routed to a mono bus came out 3 dB quieter.** It went through the stereo panner and was then summed back to mono. Mono into mono now plays at full level. Upstream wrote a test that expects the old −3 dB, so this one needs their agreement before a PR.
  - **A Maximizer (or any lookahead plugin) on the Master made every bounce start 71 samples late (1.5 ms) and lose its last 71 samples.**
  - **Fast volume rides could be skipped.** The fader only looked at the start and end of each audio block, so a short dip inside a block didn't happen. The result also depended on the buffer size, so a bounce could sound different from playback.
  - **Fade-in and fade-out could overlap on a short clip** and dip its middle by up to 12 dB.
- **Opening long files is faster and uses less memory** (results identical):
  - WAV/AIFF decoding now runs on all cores: an hour of 32-bit float stereo decodes in 0.5 s instead of 1.7 s on this 4-core cloud machine. The Z13's 16 cores should do better.

- **MP3 export: first two pieces done** on `feat/mp3-export`: the audio analysis stage, frame layout and quantizer. It isn't usable yet, so there's nothing to listen to at 96 or 128 kbps.
- **MP3 is now blocked on one decision from you.** The encoder needs the standard's Huffman code tables. The sandbox's safety check refused the script that converts minimp3's public-domain tables (see Needs Ian).

- **Two more mixer findings are reported but not fixed** because they are design calls for upstream: Write-mode automation, and swapping two copies of the same plugin. A few MIDI-only bugs are reported too (section 5).

## 6. Work done

- **`fix/master-insert-latency`**: the Master's insert lookahead is now part of the mix latency, so `render_range` removes it. Test: an impulse at sample 1000 and one near the end both come out at the right place with a Maximizer on the Master. Worth an upstream PR.
- **`fix/mono-bus-unity-gain`**: mono into mono has no panner, so it is unity gain. Stereo and wider sources still fold to mono at −6 dB. This updates upstream's `surround_busses_and_master_fader` test. Behaviour change; upstream PR only with their agreement.
- **`fix/automation-block-independent`**: the fader samples its automation on a 32-sample grid fixed to the timeline: the first and last sample of each cell, ramped in between. A step on a cell edge stays a step, and the output is identical for 64-, 333- and 1024-sample blocks. Worth an upstream PR, but coordinate with #210.
- **`fix/fades-never-overlap`**: trims shrink both fades in proportion. A newly created fade shortens the other one, through new `Clip::set_fade_in` / `set_fade_out`. Worth an upstream PR.
- **`perf/import-resample-memory`**: new `dsp::offline::resample_in_place`, used by import and session load. Same output (tested), same speed (23.6 vs 23.8 s for 10 min stereo). Peak memory for that resample: 435 MB → 331 MB. For a 3-hour 44.1 kHz stereo import that is roughly 7.9 → 6 GB at the resample step. Cloud CPU, not the Z13; relative only.
- **`perf/parallel-wav-decode`**: the WAV/AIFF readers split long files into one run of frames per core (up to 16), with bit-identical output tested for 8/16/24-bit, float32 and float64. Short files and wasm stay on one thread. One hour of 48 kHz stereo, best of 3: float32 1.68 → 0.50 s, 24-bit 2.96 → 1.12 s. On test file A: 0.115 → 0.035 s, with the same sample hash. Cloud CPU, not the Z13; relative only.
- **`feat/mp3-export`** (G-21, not wired into `encode` yet):
  - Increment 1: the analysis filterbank. The standard's 512-entry window table came from minimp3's folded (CC0) copy: I matched its columns by continuity and checked the result two ways. Its sum is 64 × 2^16, within rounding. A reference decoder back end, written from the standard's description, gets the input back at 84 dB SNR with a 1057-sample delay, the same delay real decoders report.
  - Increment 2: frame header, CBR frame sizes and 44.1 kHz padding, bit writer, side information, and the quantizer. Each is checked against values from the standard.
  - What a listener would hear: nothing yet; there is no playable file until the Huffman stage lands.
- **Test audio:** downloaded test file A only (3.5 min, 32-bit float stereo, 48 kHz, peak 0 dBFS), used it for the decode check, and deleted it.
- Item 4 write-ups: unchanged (in STATE.md).
